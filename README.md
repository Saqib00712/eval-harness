# eval-harness

A reusable, production-grade evaluation platform for AI systems — RAG
applications, plain LLM apps, agents, classifiers, structured-output
systems. Answers one question: **how do we automatically know whether an
AI system is getting better or worse?**

Built day-by-day as Project 2 of a larger AI-engineering curriculum.
Project 1 (`production-rag`, a separate repo) is one example system this
harness will evaluate — this package never depends on it.

- `eval_harness/system_output.py` — `SystemOutput`: the standardized result a system hands back.

## Setup

```
pip install -r requirements-dev.txt -r requirements-openai.txt -r requirements-httpx.txt
pytest -v
```

No `OPENAI_API_KEY` required for the full `348 passed, 4 skipped` suite —
only for `tests/live/` (which self-skip without one). But the `openai`
package itself (`requirements-openai.txt`) DOES need to be installed for
3 *unit* tests (`test_openai_embedding_provider.py`,
`test_openai_json_llm.py`) — they test construction/wrapping only, no
real network call, but `pytest.importorskip("openai")` means they skip
silently if the package isn't present. With `requirements-dev.txt`
alone, the suite reports `345 passed, 4 skipped`, not `348 passed, 4
skipped` — both are "fully passing," just a different total depending on
what's installed. `requirements-httpx.txt` is for the real
`ProductionRagAdapter` HTTP transport and isn't needed to run the test
suite at all (`FakeHttpClient` covers every adapter test).

## CLI

```
python -m eval_harness.cli validate-dataset datasets/sample_eval_v1.json
python -m eval_harness.cli demo
python -m eval_harness.cli compare baseline_run.json candidate_run.json
python -m eval_harness.cli quality-gate candidate_run.json --baseline baseline_run.json --min-pass-rate 0.9
```

Each command's exit code is CI-usable: 0 for pass/valid, 1 for fail/invalid.
